# Qwen3.8-27B / 旧款昇腾 910 优化验收报告

验收日期：2026-09-19。交付版本：2026.09.19 experimental。

## 最终效果

在 6 张旧款 Ascend 910 上，固定 64-token 测试的最终解码速度为 **5.670 token/s**。相对初始可运行版 **3.672 token/s**，速度提高 **54.42%**，生成阶段时间减少 **35.24%**；相对上一轮 **4.961 token/s** 再提高 **14.30%**。

| 阶段 | 63 次 decode 耗时 | 解码速度 |
|---|---:|---:|
| 初始可运行适配 | 17157.19 ms | 3.672 token/s |
| 原生布局 GDN + 单 token SSM | 13940.24 ms | 4.519 token/s |
| 加入隔离 CANN 缓存修复 | 12699.22 ms | 4.961 token/s |
| 最终镜像，第 1 次 | 11103.529 ms | 5.674 token/s |
| 最终镜像，第 2 次 | 11118.029 ms | 5.666 token/s |

最终汇总用两次总步数除以总 decode 时间。历史阶段各一次，最终阶段两次；不声称统计显著性。各阶段固定 64-token 输出文本完全一致。计时不含完整冷启动、权重加载、HTTP 和提示词处理；详细协议见 [BENCHMARKS.md](BENCHMARKS.md)。

## 本轮具体修改

1. **Gated DeltaNet**：直接读取 GGUF 的原生 Q/K/head 布局及紧凑 g/beta，减少逐头 staging 和小块设备拷贝；保留旧路径作为后备。
2. **SSM 卷积**：对 10240 通道、4 tap、T=1 编写专用 FP32 内核，避免通用卷积在 decode 中的额外开销。
3. **CANN 缓存修复**：移植上游缓存对象内部 kernel name 指针修复，使多卡执行器缓存路径可用；仅用进程级 LD_PRELOAD，不替换已安装 SDK。
4. **RMS**：为五种真实形状编写归一化内核，包括 L2 等价路径，减少通用操作拆分。
5. **RoPE**：支持模型 IMROPE 语义与保留尾部维度；decode 连续 T=1 使用融合内核，其他支持形状保留组合实现。
6. **KV SET_ROWS**：只对图构建中明确标记的 KV 更新启用；K 连续写，V 按对齐块读改写，完整缓存逐位检查。

所有优化都有形状、布局、类型或来源限制。完整契约见 [OPERATORS.md](OPERATORS.md)，变量和参数见 [PARAMETERS.md](PARAMETERS.md)。

## 正确性与硬件验证

- 最终清理后的独立镜像完成算子 suite，GDN/SSM、5 个 RMS 形状、32 组 RoPE、28 组 SET_ROWS 比较通过。
- 原生 GDN 在前一阶段另做 128 步 NPU 累积测试，状态最大绝对误差约 3.28e-7，输出约 1.16e-8。这个结果与镜像内单步 suite 分开记录。
- 最终镜像四个短模型回归全部通过：391、北京、Python 回文函数、391。重复请求没有在本次测试中破坏状态。
- 清理 RPATH 后的缓存库重新进行链接和模型验收，依赖解析通过。

短回归和算子精度检查不等于完整模型能力评测。固定输出长度会截断 RAG 说明，不能作为完整回答示例。

## 模型与精度

输入为 Unsloth Qwen3.8-27B UD-Q4_K_M GGUF，运行文件由它展开为 FP16 存储，文件为 54,657,735,584 字节。**展开不能恢复 Q4 已丢失的精度，不能称为官方原始 FP16 模型。** 模型来源与两份 SHA256 都在 manifest。

本次为 NPU 与 CPU 混合路径，不能声称全算子都在 NPU 或所有内部计算均为 FP32。尤其兼容性通用 CANN 路径允许某些内部 FP16 运算；原创内核的精度契约单独记录。

## 尝试过但未启用

- 激活预转换 FP16 再矩阵乘：输出一致，但没有速度收益，工作区未减少，未加入默认路径。
- Weight NZ：实际硬件返回不支持，默认关闭。
- 四卡运行：权重加载之后计算工作区分配失败；更换分配器和试非均分都未通过。六卡是本次验收可用配置，不能推导出硬件只能双卡，也不能把失败归因为卡间分配不均。

还能继续研究矩阵乘/矩阵向量专用实现、更多融合与调度开销，但这些需要新的 profiling、算子设计和精度测试。本报告只计入已经测到收益并通过验收的改动，不承诺未经验证的后续速度。
