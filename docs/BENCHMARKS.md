# 性能测量协议

## 可比较的固定输出实验

- 同一主机、同一 Qwen3.8-27B Q4 展开权重、相同设备 2—7。
- 相同提示词：`用中文详细解释检索增强生成系统如何完成文档解析、检索、重排和答案生成。`
- 模板后 33 个输入 token；输出预算 64，未提前 EOS；greedy，关闭思考。
- ctx=256、n_batch=64、n_ubatch=32、8 个 CPU 线程、单请求。
- 不设置 `GGML_CANN_PROFILE_SYNC`，关闭 Flash Attention，关闭 Weight NZ。
- 64 个生成 token 中，第一个来自 prefill，decode 计数为 63。速率公式是 `1000 * n_eval / t_eval_ms`。

历史三个阶段为各一次测量，日志以 `historical-` 开头。最终镜像连续启动两次独立容器，每次重新加载权重，结果为 `final-benchmark-1.jsonl` 和 `final-benchmark-2.jsonl`。汇总使用两次 decode 总步数除以总时间；样本数小，只能说明本机本配置的复测结果，不是严格统计或跨平台榜单。

比较的是“初始可运行适配版 → 优化版”，初始版已包含跑通模型所需的兼容性补丁，并非未经改动的上游 llama.cpp。历史使用私有测试入口，最终使用公开命名参数入口；核对了相同模型、模板、token 数、输出文本和计时口径。历史数据没有在最终镜像里倒退重跑，按阶段实测呈现。

## 时间口径

JSON 的 `t_eval_ms` 是模型 decode 计时，`t_p_eval_ms` 是提示词计算时间。两者不包含完整的进程创建、权重磁盘读取、模型图初始化或 HTTP 开销。`t_load_ms` 沿用上游 context 计数语义，不能当完整冷启动测量。

固定 64-token 测试会在长度上限处截断回答，输出不是完整 RAG 说明。这不属于回答质量失败，也不应将截断文本作为完整问答效果展示。

## 正确性验收

独立容器运行四个回归请求：17×23→391、中国首都→北京、Python 回文函数、再次17×23→391。逐请求检查成功，说明短文本路径、代码输出和重复请求没有在本次测试中破坏。

算子验证还覆盖 GDN、SSM、5 种 RMS、32 组 RoPE 和 28 组 SET_ROWS 全缓存比较。GDN 的历史 128 步 NPU 累积验证与最终镜像中的单步后端测试分开记录，详见 OPERATORS.md。这些测试不能代替完整模型基准或证明原始 FP16 权重精度。

## profiling 与失败尝试

同步 profiling 每个算子都等待，会改变整体执行时序，不能把其总耗时当真实 token/s。它仅用来定位 RMS、RoPE、KV 更新等可优化路径。

矩阵乘预转换没有实测收益；Weight NZ 返回不支持；四卡工作区分配失败。这些结果保留在优化报告，不进入最终默认配置。后续若改 context、权重或卡数，需要重新记录同口径基线。
